# Grok Bot Orchestrator

Готовый пакет для главного оркестратора на [x.ai/bot](https://x.ai/bot).

Grok Bot **не даёт** выбрать окно контекста и не даёт ручной compact. Каждый ход агента заново читает историю чата и тратит недельный usage. Этот репозиторий учит оркестратора не тащить полный контекст в один тред: узкая роль, файлы на VM как источник правды, отдельные каналы на задачу, специалисты на грязную работу.

## Что внутри

| Файл | Куда вставлять |
| --- | --- |
| [`bot/DESCRIPTION.md`](bot/DESCRIPTION.md) | Edit Profile → Description |
| [`bot/FIRST-MESSAGE.md`](bot/FIRST-MESSAGE.md) | первое сообщение после создания бота |
| [`workspace/`](workspace/) | скопировать на облачный компьютер бота |

## Быстрый старт

1. Создай бота на https://x.ai/bot, имя например `Orchestrator`.
2. Вставь текст из `bot/DESCRIPTION.md` в Description целиком.
3. Отправь ему `bot/FIRST-MESSAGE.md`.
4. Попроси его разложить `workspace/` на своём компьютере и подтвердить пути.
5. Дальше пиши только оркестратору. Специалистов он создаёт сам, но только после твоего OK.

## Правила, из-за которых это экономит лимит

- Description = постоянные правила. Чат = только текущая задача.
- Длинная работа живёт в отдельном канале и закрывается. В главный чат возвращается короткий отчёт.
- Память чата не считается источником правды. Факты пишутся в `workspace/ops` и `workspace/memory`.
- Браузер — запасной путь. Сначала файл / шпаргалка / коннектор.
- Код и длинные агентные циклы оркестратор сам не делает: отдаёт специалисту или CLI на VM.
- Все боты аккаунта сидят на одном облачном компьютере. Отдельный бот не равен изоляции секретов.

## Что оркестратор не должен делать

- не вести один бесконечный тред «про всё»;
- не открывать браузер, пока не объяснил, почему коннектор не подходит;
- не слать наружу, не удалять, не покупать и не менять прод без явного OK;
- не плодить ботов и рутины без запроса;
- не угадывать имена полей и URL.
